# Foundry deploy

## How it works
- `Dockerfile`: stage 1 Node 22 builds `FE/` → stage 2 Go 1.26 builds `BE/` → Alpine image with `./server` + `./web`.
- `render.yaml` Blueprint: one Docker web service `foundry`, plan free, region singapore, health check `/api/health`.
- Render auto-deploys on every push/merge to `main`.

## Env vars (Render → service → Environment)
| Name | Source | Note |
|---|---|---|
| `DATABASE_URL` | Neon connection string | must include `sslmode=require` |
| `JWT_SECRET` | generated by Render | changing it logs everyone out |
| `ADMIN_EMAIL` | owner | becomes admin on registration |
| `PORT` | set by Render | server reads it |

## Local image check
`docker build -t foundry .` then `docker run --rm -p 8080:8080 -e DATABASE_URL=<url> -e JWT_SECRET=x foundry`.

## Common failures
- `Thiếu biến môi trường X` → env var missing on Render.
- `Không kết nối được database` → wrong Neon string or missing `sslmode=require`.
- Blank page on reload of a sub-route → SPA fallback in `BE/static.go` broken.
- Slow first load → Render free sleeps after 15 min idle (expected).

## Never
Commit secrets or put them in `render.yaml`; change service name/region once live.
